285: Why this exists
286: 
287: Modern coding agents are remarkably capable when given a well-defined task.
288: 
289: The harder problem is deciding what should be done next.
290: 
291: Real projects are rarely a queue of perfectly specified independent tickets. An objective may require research before implementation. Research may reveal new work. Tasks may depend on other tasks. Some questions require humans. Some approaches fail. Priorities change as evidence accumulates.
292: 
293: "tag-two" explores a simple idea:
294: 
295: Represent that evolving understanding as a persistent graph, and let agents help investigate and evolve it.
296: 
297: The graph is not primarily a backlog.
298: 
299: It is the system's current model of the problem.

303: The core idea
304: 
305: Start with an objective:
306: 
307: «Improve tag-two.»
308: 
309: An agent investigates the relevant repository and problem using its normal tools.
310: 
311: It then constructs a small graph representing useful next work:
312: 
313: Improve tag-two
314: │
315: ├── Understand current behaviour
316: │
317: ├── Investigate an important uncertainty
318: │
319: ├── Improve a demonstrated weakness
320: │   └── depends on investigation
321: │
322: └── Demonstrate the improvement
323: 
324: The graph persists independently of any model conversation.
325: 
326: Later, a node can be investigated or worked on by another agent. Its result changes the graph.
327: 
328: Over time:
329: 
330: objective
331:     ↓
332: investigate
333:     ↓
334: graph
335:     ↓
336: choose useful work
337:     ↓
338: agent works
339:     ↓
340: observe result
341:     ↓
342: update graph
343:     ↓
344: repeat

347:

349:

354: The hypothesis
355: 
356: A useful agent system does not necessarily need one enormous autonomous context.
357: 
358: Instead, it can maintain durable external state describing:
359: 
360: - what we are trying to achieve;
361: - what we currently believe;
362: - what has been discovered;
363: - what remains uncertain;
364: - what work is available;
365: - what depends on what;
366: - what has already happened;
367: - where a human is required.
368: 
369: Agents can then operate on bounded pieces of that state.
370: 
371: This potentially allows different agents, models, tools and humans to collaborate without requiring a single continuous conversation.
372: 
373: The persistent graph is the continuity.

433: Research before decomposition
434: 
435: One of the strongest lessons from the original TAG experiment is that decomposition quality depends on research quality.
436: 
437: A model shown a handful of arbitrary source excerpts will tend to generate work related to those excerpts.
438: 
439: That is not necessarily the same as work important to the objective.
440: 
441: For example, an objective such as:
442: 
443: «Improve TAG»
444: 
445: previously produced locally plausible tasks involving protocol fields, validation edge cases and CLI parsing.
446: 
447: Those tasks were not necessarily wrong.
448: 
449: The problem was that the system had insufficient understanding to know whether they mattered.
450: 
451: Therefore:
452: 
453: Do not confuse code inspection with understanding the objective.
454: 
455: Before decomposing a broad objective, an agent should be able to investigate enough context to understand:
456: 
457: 1. what the project is trying to achieve;
458: 2. what currently exists;
459: 3. what currently works;
460: 4. what has already been attempted;
461: 5. what important uncertainties remain;
462: 6. what would constitute meaningful progress.
463: 
464: The agent should use normal repository tools where possible:
465: 
466: - read files;
467: - search;
468: - inspect documentation;
469: - inspect tests;
470: - inspect relevant history;
471: - run safe/read-only commands where appropriate.
472: 
473: Do not recreate a coding agent's repository exploration abilities by manually assembling arbitrary source excerpts unless there is a demonstrated reason to do so.
